# Active Priorities Review

**Runs:** weekly

**Trigger:** once a week, or when a task visibly completes

**Purpose:** keep `Active Priorities.md` an honest picture of live work.

**Steps:**

1. Read `Vault\Active Priorities.md` in full.
2. For each open item, verify current state against the actual file/config/command — no "probably done."
3. Move verified-complete items to Done with a one-line evidence note (date + how it was verified).
4. Flag items untouched for a long time; ask the user whether to keep, reword, or drop them.
5. Surface new open work that emerged during the week but was never added.

**Files involved:**

- `Vault\Active Priorities.md`
- Whatever each priority points at (for verification)

**Done looks like:**

- Every Done item has verification evidence; every Open item is genuinely open.
- No item added and never reviewed.
- Changes reflected the same session — not "will do later."
