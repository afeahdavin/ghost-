## PES 2025 folder: two scripts audited and rewritten

Scope: `C:\Users\afeah\Desktop\PES 2025\` (named by user this session).

### `ps4_controller_lowlag.py` — rewritten

- Intention was: SDL hints (background events + hidapi DS4 backend), tight
  state-polling loop, live poll-rate printout for wired-vs-Bluetooth
  testing.
- Root problem found: line 44 was `Joystick(0)` — pad #2 was never polled
  at all. Everything it did skipped controller 2.
- Rewritten: opens every pad (incremental hotplug sync), sets HIGH process
  priority, `timeBeginPeriod(1)`, per-pad telemetry (poll rate, worst read
  gap, last-input age), `--driver hidapi|dinput`, `--priority`,
  `--duration`, ANSI in-place status block.
- Two bugs found and fixed by measurement, not guesswork:
  - `rescan()` called `pygame.joystick.quit()/init()`, which made SDL
    re-queue `JOYDEVICEADDED`, which re-triggered the rescan → 18 Hz
    rebuild loop. Replaced with incremental `sync_pads()`.
  - Priority set failed with `ERROR_INVALID_HANDLE(6)`: `GetCurrentProcess`
    handle truncated without `restype = c_void_p`. Fixed.
- Measured after fix (both interpreters): loop 18 Hz → 22,000 Hz, both pads
  polled identically, worst gap 0.38–0.68 ms, priority `ok`.
- Verified on BOTH interpreters: Python 3.14 + pygame-ce 2.5.8 (SDL
  2.32.10) and Python 3.10 + pygame 2.6.1 (SDL 2.28.4) — the latter is what
  the launchers actually use.

### `pes_boost_loop.py` — bug-fixed

- It was crashing on every run: `os.walk` yields filename strings, then the
  code called `f.stat()` on them → `AttributeError`. Confirmed in
  `pes_boost_loop.err.log` dated 2026-10-14 (died on first temp cleanup).
- Only the first matching process got HIGH priority (the launcher); the real
  game process was left at Normal. Now boosts all matches.
- Added self-priority HIGH, elevation reporting, and a per-cycle guard so
  one bad cleanup can never kill the loop again.
